# Текст в терминале: grep, sed, awk, sort, xargs

Половина работы DevOps-инженера — вытащить нужное из логов, конфигураций и вывода
команд. Умение собрать однострочник из пяти утилит экономит часы по сравнению с
ручным просмотром.

## Философия конвейера

Каждая утилита делает одно и передаёт результат дальше. `|` соединяет stdout
одной команды со stdin другой.

```bash
grep 'ERROR' app.log | cut -d' ' -f1-3 | sort | uniq -c | sort -rn | head
```

Здесь: отобрали ошибки → взяли первые три поля → отсортировали → посчитали
уникальные → отсортировали по частоте → показали топ. Такая цепочка отвечает на
вопрос «какие ошибки самые частые» без единой строки кода.

## grep: поиск

```bash
grep -i error app.log            # без учёта регистра
grep -rn 'timeout' /etc/nginx    # рекурсивно с номерами строк
grep -c 'GET /health' access.log # количество совпадений
grep -v 'debug' app.log          # инвертировать: всё, кроме
grep -E '5[0-9]{2} ' access.log  # расширенные регулярные выражения
grep -A3 -B1 'Exception' app.log # контекст
```

Важно: `grep -r` без `--include` проходит по бинарникам и может зависнуть.
Ограничивайте: `grep -rn --include='*.conf' nginx /etc`.

## cut, awk и выбор полей

`cut` работает по фиксированному разделителю:

```bash
cut -d: -f1 /etc/passwd
cut -d' ' -f1,7 access.log
```

Но `cut` не умеет «схлопывать» повторяющиеся пробелы, поэтому для логов чаще
используют `awk`:

```bash
awk '{print $1, $7}' access.log
awk '$9 >= 500 {print $7, $9}' access.log
awk -F: '{print $1, $3}' /etc/passwd
```

`awk` — маленький язык: переменные, условия, блоки BEGIN/END, массивы.

```bash
awk '{count[$7]++} END {for (url in count) print count[url], url}' access.log | sort -rn | head
```

Эта команда считает частоту URL — типичная задача анализа access-лога.

## sed: замена и удаление

```bash
sed 's/old/new/' file            # первая замена в строке
sed 's/old/new/g' file           # все замены
sed -i.bak 's/debug/info/g' app.conf   # с бэкапом
sed -n '10,20p' file             # только строки 10–20
sed '/^#/d; /^$/d' file          # убрать комментарии и пустые строки
```

`sed -i` меняет файл на месте. Всегда делайте `.bak` или проверяйте сначала без
`-i`: ошибка в регулярном выражении может испортить конфигурацию.

## sort, uniq, wc

```bash
sort file | uniq -c | sort -rn
sort -t: -k3 -n /etc/passwd      # по третьему полю как числу
sort -h sizes.txt                # человекочитаемые размеры
wc -l access.log                 # строк
```

`uniq` работает только с **соседними** одинаковыми строками, поэтому перед ним
всегда `sort`. Это одна из самых частых ошибок в однострочниках.

## xargs: превратить строки в аргументы

```bash
find . -name '*.tmp' -print0 | xargs -0 rm -f
cat hosts.txt | xargs -n1 -P4 ping -c1 -W1
```

- `-print0` + `xargs -0` безопасно обрабатывают пробелы в именах;
- `-n1` — по одному аргументу на команду;
- `-P4` — четыре параллельных процесса.

Без `-print0` файл с пробелом в имени развалится на два аргумента. Это классический
источник «rm: cannot remove».

## jq: JSON вместо grep

```bash
curl -s https://api.github.com/repos/owner/repo | jq '.stargazers_count'
kubectl get pods -o json | jq -r '.items[] | select(.status.phase!="Running") | .metadata.name'
```

`jq -r` выдаёт «сырые» строки без кавычек — удобно для конвейера. Для фильтрации
нестандартных состояний это надёжнее, чем grep по тексту.

## Практический пример: разбор access-лога

```bash
awk '{print $9}' access.log \
  | sort | uniq -c | sort -rn \
  | awk '{printf "%s %s %.1f%%\n", $2, $1, $1/NR*100}'
```

Получаем распределение кодов ответа в процентах. Дальше по такому же принципу —
топ IP, топ URL, среднее время ответа.

## Подробный разбор темы

Конвейер `grep | awk | sort | uniq` превращает поток строк в последовательность преобразований. Сначала определите структуру входа: разделитель, кодировку и возможные пустые поля. `awk` удобен для полей, `sed` — для потоковых замен, `grep` — для фильтрации, но регулярные выражения у этих инструментов могут иметь разные режимы. Проверяйте вывод на маленьком примере до запуска на полном архиве логов.

Для имён файлов с пробелами и переводами строк не полагайтесь на разбор по пробелам; передавайте нуль-терминированные имена через `find -print0` и `xargs -0`. Добавляйте `set -o pipefail`, когда ошибка ранней команды не должна маскироваться успехом последней. Не печатайте секреты в общий CI-лог, даже если фильтруете только часть строки.

## Пошаговый сценарий

![Порядок действий: Текст в терминале: grep, sed, awk, sort, xargs](assets/img/howto/02-bash--03-text-tools.svg)

1. Посмотрите несколько строк и выясните формат полей и разделителей.
2. Отфильтруйте нужные строки grep, не выводя чувствительные данные.
3. Преобразуйте поля awk/sed и передавайте имена файлов через NUL.
4. Сверьте число результатов и pipeline exit status.
