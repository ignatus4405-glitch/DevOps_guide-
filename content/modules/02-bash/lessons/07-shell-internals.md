# Как работает shell: процессы, дескрипторы, подстановки

Bash кажется простым: пишите команды, он их выполняет. Но большинство
«непонятных» багов — следствие того, как shell разбирает строку, запускает
процессы и передаёт данные.

## Порядок разбора строки

Bash применяет преобразования в определённом порядке:

1. разбиение на токены (с учётом кавычек);
2. проверка на ключевые слова и алиасы;
3. подстановки: параметры, команды, арифметика;
4. разбиение на слова (word splitting);
5. glob-подстановка;
6. удаление кавычек;
7. выполнение.

Отсюда правило: **всегда кавычки вокруг переменных** (`"$var"`), если не нужен
намеренный word splitting. Иначе пробелы и `*` превратятся в сюрприз.

```bash
file="my report.txt"
cat $file      # два аргумента
cat "$file"    # один
```

## Процессы и fork/exec

Внешняя команда — это `fork` + `exec`. Оболочка создаёт копию процесса и
заменяет её программой. Встроенные команды (`cd`, `export`, `read`) выполняются
в самом shell, поэтому `cd` в subshell не меняет каталог родителя:

```bash
( cd /tmp && pwd )   # /tmp
pwd                  # прежний каталог
```

`$!` — PID последнего фонового процесса, `$$` — PID оболочки, `$?` — код
возврата последней команды.

## Файловые дескрипторы

Стандартные потоки: 0 — stdin, 1 — stdout, 2 — stderr. Перенаправления:

```bash
cmd >out.txt 2>&1      # stdout и stderr в файл
cmd 2>/dev/null        # только ошибки в никуда
exec 3>log.txt         # открыть fd 3
echo hi >&3
```

Порядок важен: `2>&1 >file` перенаправит stderr в текущий stdout (терминал),
а stdout — в файл. Поэтому `>file 2>&1` — правильный вариант.

## Конвейеры и subshell

`a | b` создаёт два процесса; каждый элемент конвейера выполняется в subshell.
Поэтому переменная, изменённая в цикле на входе конвейера, не видна снаружи:

```bash
count=0
echo -e "a\nb" | while read -r line; do count=$((count+1)); done
echo "$count"   # 0
```

Решения: process substitution (`while ... done < <(cmd)`) или `shopt -s
lastpipe` (в bash при отсутствии job control).

## Коды возврата и `set -e`

`0` — успех, ненулевое — ошибка. `set -e` завершает скрипт при ошибке, но не
внутри `if`, `&&`, `||` и не в конвейере без `pipefail`. Полный набор:

```bash
set -euo pipefail
```

`-u` ловит необъявленные переменные, `-o pipefail` — ошибку в любом элементе
конвейера.

## Подстановки

- `$(cmd)` — результат команды;
- `${var:-default}` — значение по умолчанию;
- `${var#prefix}` / `${var%suffix}` — обрезка;
- `< file` — stdin из файла;
- `<(cmd)` — файл-дескриптор с выводом команды.

`$(...)` лучше бэктиков: читается и вкладывается.

## Почему это важно в DevOps

- неправильные кавычки ломают скрипты на путях с пробелами;
- `set -e` без `pipefail` скрывает падение в конвейере;
- потерянный код возврата превращает ошибку в «успех»;
- subshell объясняет, почему счётчик не изменился.

Понимание модели shell экономит часы отладки.

## Как проверить себя

1. В каком порядке bash разбирает строку?
2. Почему `cd` в subshell не влияет на родителя?
3. Чем `>file 2>&1` отличается от `2>&1 >file`?
4. Почему счётчик в конвейере может остаться нулём?
5. Что делает `pipefail`?

!!! tip "Практика"
    Задача «Дескрипторы» в практикуме: перенаправить потоки и проверить.

## Подробный разбор темы

Shell сначала разбирает строку, выполняет подстановки и только затем запускает процессы. Поэтому порядок важен: `"$(command)"` сохраняет пробелы в результате, а ненужное слово без кавычек может расшириться в список файлов. Дескрипторы `0`, `1`, `2` обозначают ввод, stdout и stderr; перенаправление применяется слева направо, поэтому `2>&1 >file` отличается от `>file 2>&1`.

Обычный pipeline запускает команды в отдельных процессах; переменная, изменённая внутри цикла из pipeline, может не сохраниться в родительской оболочке. Process substitution и here-doc позволяют передавать данные без временного файла, но усложняют поток управления. При разборе неожиданного поведения временно включите `set -x` с безопасной маскировкой секретов и удалите подробный trace после диагностики.
