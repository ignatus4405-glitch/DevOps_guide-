# Основы bash-скриптов

Скрипт — это файл с командами, которые выполняются по порядку. DevOps пишет скрипты
для того, что повторяется: сборка, бэкап, проверка состояния, подготовка окружения.

## Каркас любого скрипта

```bash
#!/usr/bin/env bash
# Назначение: проверка состояния сервиса и перезапуск при необходимости
# Автор: команда инфраструктуры
set -euo pipefail          # см. объяснение ниже
IFS=$'\n\t'

main() {
    local service="${1:?укажите имя сервиса}"   # аргумент обязателен
    if ! systemctl is-active --quiet "$service"; then
        echo "Сервис $service не работает, перезапускаем" >&2
        sudo systemctl restart "$service"
    fi
    echo "OK: $service"
}

main "$@"
```

| Опция `set` | Что делает | Зачем |
| --- | --- | --- |
| `-e` | выход при первой ошибке | скрипт не «проедет» дальше сломанного шага |
| `-u` | ошибка при обращении к несуществующей переменной | ловит опечатки (`rm -rf $APPDIR/` с пустой переменной) |
| `-o pipefail` | падение конвейера, если упал любой его шаг | иначе `false \| true` вернёт успех |
| `-x` | печать каждой выполняемой команды | отладка: `bash -x script.sh` |

!!! danger "Осторожно"
    `set -e` **не спасает** от `rm -rf "$DIR/"` в самом начале скрипта: переменная
    ещё не задана, но `set -u` здесь как раз выручит. Дополнительно проверяйте пути:
    `[[ -n "$DIR" && "$DIR" == /opt/* ]] || exit 1`.

## Переменные и подстановки

```bash
NAME="production"                 # без пробелов вокруг =
readonly LOG_DIR="/var/log/app"   # нельзя переопределить
echo "${NAME}"                    # фигурные скобки для однозначности
echo "${NAME}_api"                # production_api

# Значения по умолчанию и проверки
: "${API_URL:?API_URL не задан}"       # падать, если переменной нет
level="${LOG_LEVEL:-info}"             # значение по умолчанию
port="${PORT:-8080}"

# Подстановка команд
commit="$(git rev-parse --short HEAD)"
files_count="$(ls -1 /var/log/*.log 2>/dev/null | wc -l)"

# Арифметика
retries=$((attempts + 1))

# Длина строки, удаление префикса/суффикса
name="app-v1.2.3.tar.gz"
echo "${name%.tar.gz}"       # app-v1.2.3   (убрать суффикс)
echo "${name%%.*}"           # app-v1        (убрать с первого .)
echo "${name#app-}"          # v1.2.3.tar.gz
```

**Разница кавычек** — источник половины ошибок в скриптах:

| Форма | Поведение | Когда использовать |
| --- | --- | --- |
| `"$VAR"` | подстановка без разбиения по пробелам | всегда по умолчанию |
| `$VAR` | разбивается по IFS, работает glob | почти никогда |
| `'$VAR'` | литерал | когда нужен точный текст |

## Условия и проверки

```bash
if [[ -f /etc/app/config.yml ]]; then
    echo "конфиг есть"
elif [[ -d /etc/app ]]; then
    echo "каталог есть, конфига нет"
else
    echo "нет ничего" >&2
    exit 1
fi

# Проверки файлов и строк
[[ -e path ]]  # существует
[[ -f path ]]  # обычный файл
[[ -d path ]]  # каталог
[[ -x path ]]  # исполняемый
[[ -z "$s" ]]  # пустая строка
[[ -n "$s" ]]  # непустая строка
[[ "$a" == "$b" ]]   # равенство строк
[[ "$n" -gt 10 ]]    # числовое сравнение
[[ "$s" =~ ^v[0-9]+ ]]  # регулярное выражение

# Проверка команды
command -v docker >/dev/null 2>&1 || { echo "нужен docker" >&2; exit 1; }
```

Используйте `[[ ]]` внутри bash-скриптов (это встроенная конструкция, безопаснее
`[ ]`) и `(( ))` для арифметики. `[ ]` остаётся для POSIX-совместимых скриптов `sh`.

## Циклы и обработка списков

```bash
for host in web1 web2 web3; do
    ssh "$host" "uptime" || echo "недоступен: $host" >&2
done

while IFS= read -r line; do
    echo "строка: $line"
done < list.txt            # правильный безопасный способ читать файл построчно

for file in /var/log/*.log; do
    [[ -e "$file" ]] || continue      # защита от пустого glob
    gzip -k "$file"
done

for i in {1..5}; do echo "попытка $i"; done
```

!!! warning "Важно"
    `for f in $(ls)` ломается на пробелах в именах. Используйте `for f in /path/*`
    (glob) или `find ... -print0 | while IFS= read -r -d '' f`.

## Функции, аргументы, коды возврата

```bash
usage() { echo "Использование: $0 <env> [--dry-run]" >&2; }

log() { echo "$(date -Is) [$1] ${*:2}"; }   # уровень, затем сообщение

backup() {
    local src="$1" dst="$2"
    tar czf "$dst" -C "$(dirname "$src")" "$(basename "$src")" || return 1
    return 0
}

log INFO "старт"
backup /opt/app/data /backup/app-$(date +%F).tgz || { log ERROR "бэкап не удался"; exit 1; }
```

Правильные скрипты **пишут в stderr** сообщения об ошибках (`>&2`) и возвращают
корректный код: `exit 0` при успехе, `exit 1..n` при конкретной ошибке.
В CI это определяет результат шага.

## Отладка

```bash
bash -n script.sh        # проверка синтаксиса без выполнения
bash -x script.sh        # трассировка команд
shellcheck script.sh     # статический анализ (обязателен в CI)
```

`shellcheck` находит реальные баги: необъявленные переменные, `ls | grep` вместо glob,
`rm -rf $VAR` без кавычек, отсутствие `set -e`. Подключите его в pre-commit или CI —
это дешевле, чем искать причину аварии ночью.

## Массивы и ассоциативные массивы

Bash умеет не только скаляры. Массив — список, ассоциативный массив — словарь.

```bash
servers=(web-1 web-2 db-1)
echo "${servers[0]}"        # web-1
echo "${#servers[@]}"       # 3
for host in "${servers[@]}"; do ssh "$host" uptime; done

declare -A ports=([web]=80 [api]=8080 [db]=5432)
echo "${ports[api]}"
for key in "${!ports[@]}"; do echo "$key=${ports[$key]}"; done
```

Кавычки вокруг `"${servers[@]}"` обязательны: без них элементы с пробелами
развалятся. `"${#arr[@]}"` — количество элементов, `"${arr[@]:1:2}"` — срез.

## Подстановки, которые экономят строки

| Выражение | Значение |
| --- | --- |
| `${VAR:-default}` | значение или default, если пусто |
| `${VAR:=default}` | присвоить default, если пусто |
| `${VAR:?error}` | выйти с ошибкой, если пусто |
| `${VAR%%.*}` | отрезать самое длинное совпадение справа |
| `${VAR##*/}` | имя файла без пути |
| `${VAR/old/new}` | заменить первое вхождение |

Пример разбора имени артефакта:

```bash
file=/srv/releases/app-1.4.2.tar.gz
base=${file##*/}        # app-1.4.2.tar.gz
name=${base%%.*}        # app-1.4.2
version=${name##*-}     # 1.4.2
```

Это работает быстрее и надёжнее, чем `cut`/`sed`, и не требует внешних процессов.

## Процессы и фоновые задачи

```bash
command &            # в фоне
jobs -l              # список фоновых задач
wait                 # дождаться всех
wait $!              # дождаться конкретного
fg %1                # вернуть в терминал
```

`$!` — PID последнего фонового процесса. В скриптах это основа простого
параллелизма: запустить N задач, затем `wait`.

```bash
for host in "${servers[@]}"; do
  ssh "$host" 'systemctl is-active app' &
done
wait
```

Такой цикл проверяет 20 серверов за время одного, а не последовательно.

## Короткое резюме

- Каркас скрипта: shebang, `set -euo pipefail`, функция `main`, обработка аргументов.
- Кавычки вокруг переменных — правило по умолчанию; `[[ ]]` вместо `[ ]`.
- Ошибки пишутся в stderr, код возврата важен для CI.
- `shellcheck` и `bash -x` — рабочие инструменты отладки.

## Подробный разбор темы

Перед запуском сценария проверьте три вещи: кто его запускает, из какой директории и какие данные он изменяет. Кавычки вокруг `"$variable"` сохраняют пробелы и предотвращают разбиение на несколько аргументов; одинарные кавычки не выполняют подстановку, двойные — выполняют переменные и часть escape-последовательностей. Для проверки результата смотрите `$?` сразу после команды, иначе его перезапишет следующая.

Небольшой скрипт должен иметь явный контракт: обязательные аргументы, ожидаемый формат входа, код `0` при успехе и ненулевой при ошибке. `set -euo pipefail` полезен, но не заменяет обработку ошибок: команды в условии, pipeline и подстановка могут вести себя иначе, чем ожидается. Проверьте сценарий на пустом вводе, путях с пробелами и недоступном файле.
