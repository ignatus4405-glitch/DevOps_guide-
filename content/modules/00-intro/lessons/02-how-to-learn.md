# Как учиться этому курсу (и не бросить)

Курс построен как **тренажёр**, а не как справочник. Каждый модуль содержит:

1. **Уроки** — точные объяснения с иллюстрациями и готовыми командами.
2. **Практику** — задачи с автопроверкой введённых команд прямо в приложении.
3. **Тест** — проверка знаний по модулю с разбором каждого ответа.

![Дорожная карта](assets/img/career-roadmap.svg)

## Ритм обучения

Оптимальный режим — **60–90 минут в день, 5–6 дней в неделю**, примерно 12 недель
до уровня Junior DevOps. Правило: каждый день должен заканчиваться
**выполненной командой**, а не прочитанной страницей.

| Недели | Модули | Ожидаемый результат |
| --- | --- | --- |
| 1–2 | Linux, Bash | уверенно работаю в терминале, пишу скрипты |
| 3 | Git | ветки, PR, разрешение конфликтов |
| 4 | Сети | понимаю DNS, порты, TLS, умею диагностировать |
| 5–6 | CI/CD, Docker | собираю пайплайн и контейнеризую приложение |
| 7–8 | Kubernetes | деплою приложение, разбираю сбои подов |
| 9 | IaC (Terraform, Ansible) | поднимаю инфраструктуру кодом |
| 10 | Облако | разворачиваю прод-контур в AWS/Yandex |
| 11 | Наблюдаемость, SRE | метрики, логи, алерты, SLO |
| 12 | DevSecOps, портфолио | защищаю проект на собеседовании |

## Как работать с уроком

!!! tip "Метод «тремя проходами»"
    1. **Первый проход** — прочитать без конспекта, понять идею и зачем она нужна.
    2. **Второй проход** — выполнить все команды из примеров на своей машине
       (Linux в WSL2, VirtualBox или бесплатный облачный инстанс).
    3. **Третий проход** — решить практические задачи без подсказок и пройти тест.

## Где практиковаться

| Способ | Плюсы | Минусы |
| --- | --- | --- |
| WSL2 на Windows | бесплатно, быстро, рядом с файлами | не настоящий сервер |
| Виртуальная машина (VirtualBox/Vagrant) | полный контроль, «сломать не страшно» | ест ресурсы ноутбука |
| Облачная ВМ (t3.micro) | как в реальной работе | нужна карта, следите за бюджетом |
| Docker Desktop | быстро поднимать сервисы | не учит администрированию ОС |

Рекомендация: **WSL2 для ежедневной практики + одна облачная ВМ** для задач про
сети и деплой.

## Привычки, которые отличают растущего инженера

- **Терминал вместо мышки.** Linux-навыки нужны постоянно, и их не подделать.
- **Notes as code.** Ведите свой `devlog` в репозитории: что делали, что сломалось,
  как починили. Через три месяца это готовое портфолио.
- **Один проект вместо десяти курсов.** Прогоните один маленький сервис через все
  этапы: Docker → CI → деплой → мониторинг.
- **Разбор ошибок.** Каждую непонятную ошибку доводите до причины, а не до
  «работает — и ладно».

## План на 12 недель

Курс рассчитан на 60–90 минут в день. Ниже ритм, который не требует героизма и
оставляет время на повторение.

| Недели | Модули | Что должно появиться в портфолио |
| --- | --- | --- |
| 1 | Введение, Linux | репозиторий `devops-journey`, шпаргалка по командам |
| 2 | Linux (глубоко), Bash | скрипт бэкапа и проверки сервиса |
| 3 | Git, сети | ветки, PR, схема сети стенда |
| 4 | CI/CD | GitHub Actions: тесты и сборка по push |
| 5 | Docker | Dockerfile и Compose-стек |
| 6–7 | Kubernetes | манифесты, деплой, отладка пода |
| 8 | IaC | Terraform-модуль и Ansible-роль |
| 9 | Облако | VPC + IAM + один managed-сервис |
| 10 | Наблюдаемость | Prometheus, дашборд, SLO |
| 11 | DevSecOps | сканирование в пайплайне, секреты |
| 12 | Финал | сквозной проект и описание в README |

Каждую четвёртую неделю оставляйте день на повторение: без него через месяц вы
помните названия, но не команды.

## Как учиться так, чтобы осталось

Курс — это карта, а не замена практике. Работающая схема:

1. **25 минут теории** — один урок, без переключений.
2. **15 минут руками** — повторить команды из урока.
3. **5 минут конспекта** — три предложения своими словами.
4. **Возврат через день и через неделю** — по конспекту.

Интервальное повторение важнее объёма: лучше пройти урок трижды, чем
прочитать три урока один раз.

## Дневник обучения

Заведите файл `learning.md`:

```markdown
## 2026-10-17
- прошёл: systemd, юниты
- сделал: unit для myapp, проверка статуса
- вопрос: почему restart не сработал при exit 1
- ответ: Restart=on-failure и код выхода
```

Через месяц дневник покажет реальный прогресс и пробелы. Он же пригодится
на собеседовании: конкретные задачи помнятся лучше, чем список тем.

## Как учиться по этому приложению

- **Читайте урок целиком**, не перескакивая разделы с командами: именно там
  объясняется, почему команда выглядит именно так.
- **Отмечайте «Урок изучен» только после практики.** Галочка без действия даёт
  ложное чувство прогресса.
- **Проходите тест после каждого модуля**, даже если кажется, что всё понятно:
  вопросы нацелены на типичные заблуждения.
- **Возвращайтесь к ошибкам.** В разборе ответа есть объяснение — это самый
  быстрый способ закрыть пробел.
- **Держите один проект.** Пять брошенных репозиториев учат хуже одного
  доведённого до работающего пайплайна.

## Что делать, когда «не понимаю»

Это нормальное состояние, а не признак неспособности. Рабочая последовательность:

1. Сформулируйте вопрос конкретно: не «как работает Kubernetes», а «почему под
   в статусе Pending, если ноды свободны».
2. Найдите минимальный эксперимент: одну команду, один манифест, один лог.
3. Прочитайте официальную документацию по этому конкретному поведению.
4. Объясните результат вслух или запишите в заметки — это проверка понимания.

Если после 30 минут эксперимента ответа нет — спросите. Умение задать точный
вопрос с контекстом (что делали, что ожидали, что получили) — профессиональный
навык, его тоже тренируют.

## Домашнее задание перед модулем 1

1. Установите WSL2 с Ubuntu (`wsl --install -d Ubuntu`) или поднимите ВМ.
2. Создайте аккаунт GitHub, если его нет.
3. Заведите репозиторий `devops-journey` и положите туда файл `README.md`
   с планом обучения.
4. Отметьте в календаре 60 минут ежедневной практики на 12 недель.

С этого репозитория начнётся ваше портфолио: в модулях 5–11 в него добавятся
Dockerfile, пайплайн, манифесты Kubernetes, Terraform и дашборд мониторинга.
