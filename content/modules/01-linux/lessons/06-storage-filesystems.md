# Диски, файловые системы и монтирование

«Закончилось место» — одна из самых частых аварий на сервере, и она редко
выглядит так, как ожидают. Разберём путь от блочного устройства до каталога и
типичные ловушки.

## Уровни хранения

| Уровень | Пример | Что означает |
| --- | --- | --- |
| Блочное устройство | `/dev/sda`, `/dev/nvme0n1` | «сырой» диск или его раздел |
| Файловая система | ext4, xfs, btrfs | структура для файлов и метаданных |
| Точка монтирования | `/var/lib/app` | каталог, куда подключена ФС |
| Логический том | LVM, mdadm | объединение дисков, снапшоты |

Посмотреть, что подключено:

```bash
lsblk -f
# NAME   FSTYPE FSVER LABEL UUID                                 MOUNTPOINTS
# sda
# └─sda1 ext4   1.0         4c1e...                              /
# nvme0n1
# └─nvme0n1p1 xfs           8a3f...                              /data
findmnt -T /var/lib/app
```

`findmnt -T` отвечает на вопрос «на какой файловой системе лежит этот путь» — это
первое, что нужно узнать, если каталог заполнился.

## Как читать df и du

`df` показывает файловые системы, `du` — размеры каталогов. Главная ошибка —
смотреть только `df -h`: он не покажет, что место занято удалённым файлом.

```bash
df -hT
df -i            # inodes: место может закончиться и по количеству файлов
du -xhd1 /var | sort -h | tail
```

Флаг `-x` не переходит на другие ФС — иначе `du /` пройдёт по сетевым монтированиям
и зависнет. `-h` — человекочитаемо, `-d1` — один уровень вложенности.

### Классическая ловушка: удалённый файл

Процесс держит открытым большой лог-файл, вы делаете `rm`, `df` не меняется.
Файл удалён, но inode живёт, пока дескриптор открыт.

```bash
lsof +L1 | head          # файлы с link count 0
: > /proc/4211/fd/7      # обнулить содержимое, не убивая процесс
```

Правильное лечение — ротация логов (`logrotate`) и перезапуск/reload процесса,
который держит дескриптор.

## Монтирование и fstab

Временное монтирование:

```bash
sudo mount /dev/sdb1 /data
sudo umount /data
```

Постоянное — через `/etc/fstab`. Ошибка в fstab делает сервер незагружаемым,
поэтому проверяют командой `mount -a` **до** перезагрузки.

```
UUID=8a3f-...  /data  xfs  defaults,nofail  0 2
```

- `UUID` устойчивее `/dev/sdb`, который может измениться после подключения диска;
- `nofail` позволяет системе загрузиться, даже если диск недоступен (важно для
  облачных ВМ с отдельным volume);
- `noatime` уменьшает запись при чтении — полезно для нагруженных ФС.

## swap и память

swap — расширение памяти на диске. Он не заменяет RAM: при активном swap
производительность падает на порядки. Проверить:

```bash
free -h
swapon --show
cat /proc/sys/vm/swappiness
```

Для серверов с приложениями `vm.swappiness` обычно снижают (10–20), чтобы ядро
предпочитало освобождать кэш, а не выгружать активные страницы. В Kubernetes swap
по умолчанию отключён, потому что планировщик рассчитывает память подов.

## LVM: зачем он нужен

LVM добавляет слой между дисками и ФС: физические тома (PV) → группа томов (VG) →
логические тома (LV). Это даёт:

- увеличение тома без переразметки: `lvextend -r +10G /dev/vg0/data`;
- снапшоты для бэкапа;
- объединение нескольких дисков.

```bash
sudo lvextend -r -L +10G /dev/vg0/data   # -r сразу расширяет ФС
```

Без `-r` нужно отдельно `resize2fs` (ext4) или `xfs_growfs` (xfs) — и это забывают.

## Что проверять при «нет места»

1. `df -h` — какая ФС заполнена.
2. `df -i` — не закончились ли inodes.
3. `du -xhd1 <точка монтирования>` — какой каталог растёт.
4. `lsof +L1` — удалённые, но открытые файлы.
5. `journalctl --disk-usage` — не съел ли место журнал.
6. `docker system df` — не накопились ли образы и тома.

Только после этого удаляют данные. `rm -rf` без понимания, что занимает место, —
способ удалить нужное и не освободить ничего.

## Подробный разбор темы

«Нет места» может означать заполненные блоки или закончились inode. Сверьте `df -h` и `df -i`, затем найдите крупных потребителей через `du -xhd1` на нужной файловой системе. Файл, который уже удалили, всё ещё занимает место, если процесс держит его открытым; это видно в `lsof +L1`. Не удаляйте случайные файлы в `/var/lib`: там могут лежать данные службы.

При монтировании важны устройство, точка подключения и параметры, с которыми система восстановит mount после перезагрузки. Проверяйте `findmnt`, UUID и `/etc/fstab`; перед перезапуском убедитесь, что запись проверяется командой `mount -a` без ошибок. Планируйте место по скорости роста данных, сроку хранения и запасу на временные файлы, а не только по текущему размеру каталога.

## Пошаговый сценарий

![Порядок действий: Диски, файловые системы и монтирование](assets/img/howto/01-linux--06-storage-filesystems.svg)

1. Сравните заполнение блоков и inode через df -h и df -i.
2. Найдите крупные каталоги и удалённые файлы, открытые процессом.
3. Проверьте mount point, UUID и параметры восстановления после reboot.
4. Освобождайте только подтверждённо ненужные данные и повторите измерение.

## Пошаговое объяснение для новичка

Сначала выполните упражнение в учебной среде или на примере из урока. Если действие меняет реальные файлы, сервер или облако, сначала проверьте цель и подготовьте откат. После каждого шага сравните результат с проверкой ниже; при неожиданном результате остановитесь.

### Шаг 1

**Что сделать.** Выполните `df -h` для свободного места и `df -i` для количества свободных индексных записей (inode).

**Как проверить.** Понятно, закончилось место в гигабайтах или закончились inode; это разные причины ошибки.

### Шаг 2

**Что сделать.** Для безопасного обзора крупных папок используйте `du -xhd1 /var 2>/dev/null | sort -h`; `lsof +L1` может показать удалённый файл, всё ещё открытый процессом.

**Как проверить.** Вы нашли, что занимает место, но не удаляете файлы журналов и данных наугад.

### Шаг 3

**Что сделать.** Выполните `findmnt` и `lsblk -f`, чтобы увидеть точки монтирования, файловые системы и UUID.

**Как проверить.** Нужный раздел подключён туда, куда ожидалось; UUID совпадает с конфигурацией.

### Шаг 4

**Что сделать.** Удаляйте только подтверждённый временный файл после проверки владельца и назначения; затем снова выполните `df -h` и `df -i`.

**Как проверить.** Свободное место увеличилось, а приложение продолжает работать; иначе остановитесь и восстановите из backup.
