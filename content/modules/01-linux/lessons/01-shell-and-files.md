# Терминал, оболочка и файловая система

**Оболочка (shell) — программа, которая читает ваши команды и запускает другие
программы.** В Linux это обычно `bash` или `zsh`. Терминал — окно, через которое
оболочка общается с вами. DevOps-инженер проводит в терминале большую часть дня,
потому что все серверы управляются именно так — по SSH, без графической оболочки.

![Файловая система Linux](assets/img/linux-filesystem.svg)

## Из чего состоит Linux

| Слой | Что это | Пример |
| --- | --- | --- |
| Ядро (kernel) | управляет процессами, памятью, устройствами, сетью | Linux 6.x |
| Дистрибутив | ядро + утилиты + пакетный менеджер | Ubuntu, Debian, RHEL, Alpine |
| Оболочка | интерпретатор команд | bash, zsh |
| Пользовательское ПО | сервисы и приложения | nginx, docker, python |

!!! note "Почему важно"
    В production чаще всего встречаются Debian/Ubuntu (пакеты `.deb`, `apt`) и
    RHEL-семейство: CentOS Stream, Rocky, AlmaLinux, Fedora (пакеты `.rpm`, `dnf`).
    Alpine (`.apk`) — в контейнерах, потому что лёгкий. Умение работать с обоими
    семействами пакетов — обязательный навык.

## Навигация: минимум, который нужен всегда

```bash
pwd                 # где я сейчас
ls -lah             # список файлов: -l подробно, -a скрытые, -h человекочитаемый размер
cd /etc/nginx       # переход в каталог
cd -                # вернуться в предыдущий каталог
cd ~                # домашний каталог пользователя
tree -L 2           # дерево каталогов до глубины 2 (пакет tree)
```

| Команда | Зачем |
| --- | --- |
| `find /var/log -name "*.log" -mtime -1` | найти логи, изменённые за сутки |
| `grep -rn "error" /etc/nginx/` | искать текст в файлах рекурсивно, с номерами строк |
| `du -sh /var/*` | сколько занимает каждый каталог внутри /var |
| `df -h` | свободное место на файловых системах |
| `stat /etc/hosts` | всё о файле: права, владелец, даты, inode |
| `file backup.tar.gz` | что это за файл на самом деле |
| `less /var/log/syslog` | постраничный просмотр (`q` — выход, `/` — поиск) |

!!! tip "Совет"
    Вместо `cat` для больших файлов используйте `less` — он не заливает экран и
    умеет поиск. А вместо `grep` по всему диску — `grep -r` в конкретном каталоге:
    так вы не убьёте диск на сервере.

## Пути, ссылки и специальные файлы

```bash
ln -s /opt/app/releases/v2 /opt/app/current   # симлинк: «указатель» на версию
ls -l /opt/app/current                        # lrwxrwxrwx ... current -> releases/v2
```

Симлинк — основа «атомарных» деплоев: вы выкладываете новую версию рядом и одним
переключением ссылки `current` переводите сервис на неё (так работает Capistrano).
Симлинк можно удалить, не задев данные, а `rm -r` настоящего каталога — уничтожит данные.
Отсюда правило: **`rm -rf` применяем только к путям, которые осознанно проверили**.

Три важных кластера путей:

- `/etc` — конфигурация (правится руками или Ansible);
- `/var` — изменяемые данные: логи, базы, очереди (растёт, следите за местом);
- `/usr/local` и `/opt` — сторонний софт, который вы ставите сами.

## Потоки, конвейеры, перенаправление

Любая программа имеет три потока: `stdin` (0), `stdout` (1), `stderr` (2).

```bash
journalctl -u nginx > /tmp/nginx.log 2>&1   # stdout и stderr в файл
ls /nonexistent 2>/dev/null                 # ошибки в «никуда»
cat access.log | grep 500 | wc -l           # конвейер: сколько ошибок 500
grep -c "ERROR" app.log || echo "нет ошибок" # код возврата: 0 — успех, не 0 — сбой
```

**Код возврата** (`$?`) — фундамент автоматизации: именно на нём строятся условия
`if` в bash и шаги CI, где ненулевой код означает падение шага.

## Переменные окружения и конфигурация оболочки

```bash
export APP_ENV=production      # переменная для текущей сессии и её потомков
echo $PATH                     # где оболочка ищет команды
printenv | sort | head         # все переменные окружения
```

Файлы, которые читает bash при входе: `~/.bashrc` (интерактивные сессии),
`~/.profile`, `/etc/profile` (для всех пользователей). Правило: личные алиасы —
в `~/.bashrc`, общие для сервисов — через systemd и `.env`-файлы, а не в профиль root.

## Типичные ошибки новичка

| Ошибка | Последствие | Как избежать |
| --- | --- | --- |
| Работа от root «чтобы не спрашивало пароль» | одна опечатка убивает сервер | использовать `sudo` по необходимости |
| `rm -rf $DIR/` без проверки `$DIR` | удаление корня, если переменная пуста | `[ -n "$DIR" ] && rm -rf "$DIR"` |
| Правка конфига без бэкапа | сервис не стартует, откатить нечем | `cp app.conf app.conf.bak` + Git |
| `chmod 777` для «пусть работает» | дыра в безопасности | группа + правильные права |
| Игнорирование кода возврата | скрипт «прошёл», а задача не выполнена | `set -euo pipefail` в скриптах |

## Горячие клавиши и работа с историей

Терминал экономит часы, если пользоваться им осознанно.

| Сочетание | Действие |
| --- | --- |
| `Ctrl+R` | поиск по истории команд |
| `Ctrl+A` / `Ctrl+E` | в начало / в конец строки |
| `Ctrl+U` / `Ctrl+K` | удалить до / после курсора |
| `Ctrl+W` | удалить слово |
| `Alt+.` | вставить последний аргумент прошлой команды |
| `!!` | повторить прошлую команду |
| `!$` | последний аргумент прошлой команды |

Последние два особенно полезны: `sudo !!` повторяет команду с правами root,
а `cat !$` открывает файл, который вы только что указали.

## Полезные приёмы работы с файлами

```bash
find /var/log -name '*.log' -mtime +7 -delete      # старые логи
find . -type f -size +100M -printf '%s %p\n' | sort -n | tail
ln -s /opt/app/current /opt/app/releases/v42       # атомарное переключение
stat -c '%U %G %a %n' file                          # владелец, группа, права
```

Символическая ссылка — основа blue-green деплоя без контейнеров: приложение
смотрит в `current`, а переключение — одна атомарная операция.

## Почему «работает у меня» — проблема окружения

Файловая иерархия стандартизирована (FHS), и от неё зависит переносимость:

| Каталог | Что там | Кто пишет |
| --- | --- | --- |
| `/etc` | конфигурация | администратор |
| `/var/lib` | состояние сервисов | приложение |
| `/var/log` | логи | сервис/журнал |
| `/opt` | сторонние приложения | установщик |
| `/tmp` | временные файлы | все, очищается |

Если приложение пишет данные в `/opt/app` или `/tmp`, при обновлении или очистке
данные пропадут. Правильное место состояния — `/var/lib/<app>` или внешний том.

## Короткое резюме

- Оболочка (`bash`) — основной интерфейс управления сервером.
- Знание типовых каталогов (`/etc`, `/var`, `/opt`) ускоряет диагностику.
- Три потока и перенаправление — основа конвейеров и логов.
- Код возврата определяет поведение скриптов и CI.

## Подробный разбор темы

Путь `/var/log/app.log` начинается от корня файловой системы, а `../logs/app.log` зависит от текущего каталога. Поэтому в скриптах, службах и CI фиксируйте рабочую директорию явно, а пробелы и специальные символы заключайте в кавычки. Команды вроде `find` и `grep` удобны для массового поиска, но перед изменением файлов сначала выведите список совпадений и проверьте его глазами.

Разбирайте задачу с безопасных команд: `pwd` показывает контекст, `ls -la` — скрытые файлы и права, `stat` — владельца и временные метки, `file` — тип содержимого. Для путей, начинающихся с дефиса, используйте `--`, чтобы аргумент не был воспринят как параметр. Это снижает риск ошибочной работы не в том каталоге или с не тем набором файлов.

## Пошаговый сценарий

![Порядок действий: Терминал, оболочка и файловая система](assets/img/howto/01-linux--01-shell-and-files.svg)

1. Проверьте текущий каталог и выберите точный путь к нужному файлу.
2. Осмотрите тип, владельца и права до любого изменения.
3. Используйте кавычки для путей с пробелами и `--` перед именами с дефисом.
4. Повторно проверьте список файлов и результат безопасной операции.
