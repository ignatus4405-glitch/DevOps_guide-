# FinOps: unit-экономика и управление затратами

Облако превращает капитальные затраты в операционные: счёт растёт каждый день.
FinOps — практика, которая связывает инженерные решения с деньгами.

## Три фазы

1. **Inform** — видимость: кто, на что и сколько тратит.
2. **Optimize** — rightsizing, скидки, устранение простоя.
3. **Operate** — регулярный процесс, бюджеты, ответственность.

Без видимости оптимизация превращается в угадывание.

## Теги и аллокация

Минимальный набор:

- `owner` — команда;
- `project`/`service`;
- `env` — prod/staging/dev;
- `cost-center`.

Теги должны быть обязательными — через политику, а не «попросили». Иначе
30 % счёта окажется «без владельца».

## Unit-экономика

Смотрите не только абсолютный счёт, а стоимость единицы:

```text
$ на 1000 запросов
$ на активного пользователя
$ на заказ
```

Рост счёта при росте продукта — нормально. Плохо, когда unit-cost растёт.

## Рычаги

| Рычаг | Экономия | Риск |
| --- | --- | --- |
| rightsizing | 10–30 % | деградация |
| Spot/preemptible | 60–90 % | прерывание |
| committed use | 20–40 % | обязательство |
| storage tiers | 30–70 % | время доступа |
| удаление idle | 100 % | забытые зависимости |

## Spot без боли

- только stateless/batch;
- несколько типов инстансов;
- graceful shutdown;
- checkpointing;
- не для единственной реплики БД.

## Бюджеты и алерты

```bash
aws budgets create-budget --account-id ... --budget file://budget.json
```

Алерты на 80 % и на прогноз 100 %. Прогноз ловит тренд раньше факта.

## Культура

- счёт виден командам;
- решения обсуждаются с ценой;
- оптимизация не ломает SLO;
- «дешевле» — не всегда «лучше».
