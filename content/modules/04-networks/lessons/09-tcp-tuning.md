# TCP в реальной сети: окна, очереди, keepalive

TCP скрывает сложность сети, но не отменяет её. Когда throughput ниже
ожидаемого, а приложение «не виновато», смотрите на окна, потери и очереди.

## Окно и пропускная способность

Пропускная способность ограничена:

```text
throughput ≤ window / RTT
```

При RTT 100 мс и окне 64 КБ максимум ≈ 5 Мбит/с, сколько бы ни было канала.
Поэтому современные стеки используют window scaling и autotuning.

Проверка:

```bash
ss -tin
# отправное и приёмное окно, cwnd, rtt
```

## Congestion control

`cwnd` растёт при успешных подтверждениях и падает при потерях. Алгоритмы:

- **cubic** — по умолчанию в Linux, агрессивен при малых потерях;
- **bbr** — моделирует bottleneck, лучше на длинных каналах с потерями;
- **reno** — старый, предсказуемый.

Смена алгоритма — не универсальное лекарство. BBR может вытеснять cubic и
создавать несправедливость в общих сетях.

## Очереди сокетов

`ss -lnt` показывает `Recv-Q` и `Send-Q`. Для слушающего сокета `Recv-Q` —
accept backlog. Если он растёт, приложение не успевает принимать соединения.

```bash
ss -lnt 'sport = :443'
cat /proc/sys/net/core/somaxconn
```

## TIME_WAIT и порты

Короткоживущие соединения оставляют TIME_WAIT. Тысячи таких сокетов — норма,
но при нехватке эфемерных портов новые соединения падают.

```bash
ss -tan state time-wait | wc -l
cat /proc/sys/net/ipv4/ip_local_port_range
```

Лечение: пулы соединений, keepalive, `tcp_tw_reuse` (осторожно), уменьшение
числа коротких соединений.

## Keepalive

Долгие соединения через NAT/firewall должны «дышать»:

```bash
cat /proc/sys/net/ipv4/tcp_keepalive_time
```

Приложение может использовать свои heartbeat. Без них соединение считается
мёртвым только после нескольких минут, а запросы уходят в никуда.

## Retransmit и потери

```bash
nstat -az | grep -i retrans
ss -tin | grep retrans
```

Высокий процент ретрансмиссий — потери на пути, перегрузка или дуплексный
mismatch. Проверьте `tc qdisc`, ошибки интерфейса (`ip -s link`).

## Nagle и delayed ACK

Алгоритм Nagle объединяет мелкие пакеты, delayed ACK задерживает подтверждение.
Вместе они дают задержку до 40 мс. Для latency-критичных протоколов включают
`TCP_NODELAY` (обычно на клиенте/сервере приложения).

## Буферы

```bash
sysctl net.ipv4.tcp_rmem net.ipv4.tcp_wmem
```

Слишком маленькие — не используют канал; слишком большие — bufferbloat.
Автотюнинг обычно лучше ручных значений.

## Методика

1. Измерьте RTT и потери (`mtr`, `ping`).
2. Посмотрите окна и cwnd (`ss -tin`).
3. Проверьте очереди и backlog.
4. Сравните с baseline в том же регионе.
5. Меняйте по одному параметру.

## Как проверить себя

1. Как окно и RTT ограничивают throughput?
2. Что означает растущий `Recv-Q` у слушающего сокета?
3. Зачем keepalive для долгих соединений?
4. Что такое bufferbloat?
5. Почему TCP_NODELAY важен для RPC?

!!! tip "Практика"
    Задача «Диагностика TCP» в практикуме: найти узкое место по `ss`.

## Подробный разбор темы

Throughput ограничивается не только полосой канала, но и окном передачи относительно RTT. При высокой задержке маленькое окно не позволяет держать линию заполненной; packet loss заставляет TCP повторно передавать данные и уменьшать темп. Смотрите retransmissions, RTT и очередь на обеих сторонах, прежде чем менять системные sysctl: неверный tuning может ухудшить другие соединения на хосте.

Keepalive обнаруживает некоторые «мёртвые» соединения, но не заменяет прикладной timeout и heartbeat. Очередь accept и backlog влияют на короткие всплески подключений; истощение ephemeral ports может проявиться при большом числе исходящих соединений. Измеряйте профиль до и после изменения на одном узком сценарии и фиксируйте параметры, чтобы результат можно было откатить.

## Пошаговый сценарий

![Порядок действий: TCP в реальной сети: окна, очереди, keepalive](assets/img/howto/04-networks--09-tcp-tuning.svg)

1. Снимите RTT, retransmits, throughput и очереди до настройки.
2. Проверьте, ограничивает ли окно TCP канал при данном RTT.
3. Измените только один параметр на изолированном тестовом профиле.
4. Сравните эффект на разных соединениях и сохраните откат.
