# Семантика HTTP: идемпотентность, кэш, условные запросы

HTTP — не просто «отправить JSON». Семантика методов и заголовков определяет,
как работают прокси, кэши, ретраи и браузеры. Ошибки здесь приводят к двойным
платежам и странным ответам из кэша.

## Методы и идемпотентность

| Метод | Безопасный | Идемпотентный | Тело |
| --- | --- | --- | --- |
| GET | да | да | нет |
| HEAD | да | да | нет |
| PUT | нет | да | да |
| DELETE | нет | да | нет |
| POST | нет | **нет** | да |
| PATCH | нет | нет | да |

Идемпотентность — свойство сервера: повторный PUT с тем же телом даёт тот же
результат. POST по умолчанию — нет, поэтому для платежей используют
`Idempotency-Key`.

## Коды ответов, которые важно различать

- `200/201/204` — успех;
- `301/308` — постоянный редирект (308 сохраняет метод);
- `302/307` — временный (307 сохраняет метод);
- `400` — клиентская ошибка;
- `401` — не аутентифицирован;
- `403` — аутентифицирован, но нельзя;
- `404` — нет ресурса;
- `409` — конфликт;
- `422` — валидация;
- `429` — rate limit;
- `500/502/503/504` — серверные, но причины разные.

`502` — плохой ответ upstream, `504` — таймаут upstream. Это разные диагнозы.

## Кэширование

Заголовки:

- `Cache-Control: max-age=60, public/private, no-store`;
- `ETag` — версия ресурса;
- `Last-Modified`;
- `Vary` — какие заголовки влияют на кэш.

`private` запрещает кэшировать в общем кэше (CDN), `no-store` — не хранить
вообще. `Vary: Authorization` защищает от утечки между пользователями.

## Условные запросы

Клиент присылает `If-None-Match: <etag>`. Сервер отвечает `304 Not Modified`
без тела, если версия та же. Это экономит трафик и ускоряет загрузку.

```http
GET /api/profile
If-None-Match: "v42"
→ 304
```

## Кэш и безопасность

- не кэшируйте ответы с персональными данными в общих кэшах;
- `Set-Cookie` и `Authorization` требуют аккуратного `Vary`;
- CDN должен уважать `Cache-Control`, а не кэшировать всё подряд.

## Согласование содержимого

`Accept`, `Accept-Encoding`, `Accept-Language` позволяют отдать разный формат.
`Vary` должен перечислять эти заголовки, иначе кэш отдаст не тот вариант.

## Ретраи и методы

Ретраить можно идемпотентные методы. Для POST — только с ключом идемпотентности
и ограничением попыток. Иначе повтор создаст второй заказ.

## Прокси и hop-by-hop

Заголовки `Connection`, `Keep-Alive`, `Transfer-Encoding` относятся к соединению
и не должны передаваться дальше. `X-Forwarded-For`/`Forwarded` — к клиенту,
но им нельзя доверять без проверки на границе.

## Как проверить себя

1. Почему POST не идемпотентен?
2. Чем 502 отличается от 504?
3. Что делает `If-None-Match`?
4. Зачем `Vary`?
5. Какие методы безопасно ретраить?
