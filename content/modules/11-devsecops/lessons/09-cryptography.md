# Криптография для DevOps: хэши, подписи, KMS

DevOps-инженеру не нужно проектировать шифры, но нужно понимать, что именно
защищает TLS, подпись образа и хэш пароля. Иначе выбираются неверные
инструменты.

## Хэши

Хэш — одностороннее преобразование фиксированной длины. Свойства: детерминизм,
лавинный эффект, устойчивость к коллизиям.

- SHA-256 — для целостности и подписей;
- SHA-1/MD5 — сломаны, не использовать;
- bcrypt/argon2 — для паролей (медленные, с солью).

Хэш **не шифрование**: из него нельзя восстановить данные. Пароли хранят
только как медленный хэш с солью.

## Симметричное шифрование

Один ключ для шифрования и расшифровки. Быстро, используется для данных:

- AES-GCM — аутентифицированное шифрование (confidentiality + integrity);
- ключ хранится в KMS/Vault, а не в коде.

Режим ECB не использовать: одинаковые блоки дают одинаковый шифртекст.

## Асимметричное

Пара ключей: приватный подписывает/расшифровывает, публичный проверяет/шифрует.

- RSA — старый, большие ключи;
- ECDSA/Ed25519 — короче и быстрее.

Асимметрия дороже симметрии, поэтому в TLS она используется для обмена
сессионным ключом, а данные шифруются AES.

## Подписи

Подпись доказывает авторство и целостность:

```bash
cosign sign --key cosign.key image@sha256:...
cosign verify --key cosign.pub image@sha256:...
```

Ключевая подпись требует управления ключом. Keyless (Sigstore) использует OIDC
identity и прозрачный лог, но требует проверки issuer/identity.

## TLS

TLS 1.3: ECDHE для обмена, AEAD для данных, сертификат для аутентификации
сервера. Клиент проверяет цепочку до доверенного корня. Ошибки:

- истёк сертификат;
- неполная цепочка;
- неверный hostname;
- старый протокол.

## KMS и секреты

KMS хранит ключи и выполняет операции, не отдавая ключ наружу. Envelope
encryption: данные шифруются data key, data key — master key.

Правила:

- разные ключи по средам;
- ротация;
- аудит использования;
- least privilege на decrypt.

## Ошибки

- хранить ключи в Git;
- использовать один ключ везде;
- самодельная криптография;
- логировать секреты;
- считать base64 шифрованием.

## Как проверить себя

1. Чем хэш отличается от шифрования?
2. Почему пароли хэшируют медленно?
3. Зачем асимметрия, если есть симметрия?
4. Что проверяет подпись?
5. Зачем envelope encryption?
